# Session 3 — Core pipeline: effects, silence, orchestration

**Session 3 (2026-11-09):** effects, silence removal and the batch orchestration. The whole pipeline runs from the command line: `python test/run_folder.py <folder> [--category music] [--effect ps1] [--silence] [--format ogg] [--subfolders] [--quiet-only]` (output defaults to `<folder>\unified`, Ctrl+C stops like the Stop button). `python test/check_pipeline.py` passes (~15 s); `test/check_core.py` still passes.
- **Files:** `core/effects.py` (registry `EFFECTS`, `dropdown_rows()` with the 3 header rows as `tag=None`, `describe()`, `filter_chain()`, `apply_effect()`; checks itself against `naming.EFFECT_TAGS` on import), `core/silence.py` (Slicer verbatim, FFmpeg→numpy `load_pcm()`, `remove_silence()`), `core/pipeline.py` (`Settings`, `scan()` → `ScanReport` with `.summary()` for the scan line, `run_batch()` → `BatchSummary`, `check_output_dir()`).
- **For Session 4:** the worker calls `scan(settings, runner, progress)` then `run_batch(settings, report, runner, log, progress)`. Callbacks run on the worker thread, so they should only put onto the queue. Stop = `runner.cancel()`; call `runner.reset()` before the next run. `check_output_dir()` before starting gives the "can't write" message. `Settings` field names match the `config.json` keys. Effect descriptions are all written (≤300 chars, checked).
- **Temp files are 32-bit float WAV**, decided: lossless (no double lossy encode), and float keeps the overs `volume=3dB` can add until the gain stage pulls them down. No silence removal and no effect → no temp file at all. One `afu_*` temp dir per batch in the system temp; per-file temps are deleted as soon as the file is done.
- **Two Slicer changes, flag if you disagree.** (1) `min_length` 300 instead of 3000: with 3000 the Slicer returns any file of 3 s or less untouched, i.e. nearly every sound effect. Pauses up to 0.5 s are still kept whole. (2) The -40 dB threshold follows the file's level (never above -40): silence removal runs before the level match, so a quiet recording's soft passages counted as silence. `chillnew.mp3` lost 119 of 421 s before, 63 now. Details in `docs/processing_spec.md` → Step 1. `get_rms` rewritten to give the same values at a fraction of the memory.
- **Group A returns to the source's own rate**, not the fixed 48000 in `presets.md`; checked, outputs keep 44.1k / 48k / 24k.
- **Same-output-name clash** (`door.wav` + `door.flac` forced to `.mp3`): the second file is logged as failed rather than silently overwriting the first.
- **Echo effects add their delay as a tail** (far away +60 ms, underwater +40 ms, megaphone +20 ms). Harmless.
- **Real-folder runs** (music + PS1 + silence → ogg; sfx + NES + silence, run twice with output inside input): 7/7 succeeded, the re-run skipped its own output, every output kept its rate and stays at or under -1 dBTP.
