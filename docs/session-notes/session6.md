# Session 6 — Edge cases

**Session 6 (2026-11-09):** every edge case on the list, tested by driving the real window. `python test/make_session6_samples.py` builds `test/session6_samples/` (600-file batch, 40 small files, awkward names, a 3-level tree; gitignored), then `python test/session6_edge.py [case ...]` runs 60-odd checks (cases: ffmpeg, empty, names, nested, readonly, vanish, stop, big; work copies in `test/session6_work/`, an earlier one moved to `C:\trash`). Message boxes are swapped for a recorder; "deleting" the From folder is a move to `C:\trash`. All pass, `check_core.py` and `check_pipeline.py` too.
- **Bug fixed: Start froze the window on a folder the user may not write to.** `check_output_dir()` used `tempfile`, which on Windows takes "access denied" for a name clash and retries up to `os.TMP_MAX` = 2^31 names. Now it writes its own probe file; the dialog says "Windows doesn't allow saving files there." (The read-only *attribute* on a folder is ignored by Windows; the real case is a folder without write permission, tested with `icacls /deny`.)
- **Bug fixed: memory with long files and silence removal.** A 1-hour stereo mp3 peaked at 3.8 GB (the pipe read holds the decode twice, the RMS cast the whole file to float64, the kept parts were joined into another copy). Now the decode goes to a temp file that is memory-mapped, `get_rms` works and pads a block at a time, and the output is written a block at a time: 1.1 GB private, identical output. Temp disk ~1.3 GB per stereo hour while that file is processed. The check in `check_pipeline.py` now covers multi-block lengths.
- **The folders as the cause stop the batch** (`_folder_problem()` in `core/pipeline.py`, asked when a file is missing or fails): From folder gone, To folder unwritable, disk under 20 MB free, or every remaining file gone (deleting a folder in Explorer can't remove the file FFmpeg has open, so the folder usually survives with that one file). One log line plus a warning dialog (`BatchSummary.problem`); at most the file in flight fails. Before this, every remaining file failed one by one with FFmpeg's stderr.
- **Read-only earlier output:** logged as "is already in the To folder and is read-only", the rest go on. Before, the cleanup's `unlink()` raised over FFmpeg's error and the log showed a bare `[WinError 5]`.
- **Zero audio files:** Start says so in a dialog *before* creating the To folder (it used to leave an empty `unified` behind), with an "Include subfolders" hint when there are folders inside, and the list of formats.
- **Missing FFmpeg:** the summary line's "FFmpeg not found" was wiped when a folder was picked; it stays now. Screenshot `shots/session6/no_ffmpeg.png`.
- **Fine as they were:** unicode/emoji/CJK, commas, quotes, `%d`, a leading dash, double spaces (FFmpeg args are a list and no filter embeds a path; the log box and log.txt show them); output inside input with subfolders in all three shapes (To = From\unified, To inside a subfolder with audio, To = From), each run twice; Stop mid-batch in 0.45 s, no half-written file, no FFmpeg left, Start again overwrites cleanly, no temp folder left; Stop during the folder check, then Start re-checks.
- **Large batch** (`shots/session6/big_batch.txt`): 600 files in 6 subfolders, voice + PS1 + remove silence: 523 s (0.87 s per file, check included), longest Tk event handling 54 ms (99% under 12 ms), window process 67 → 72 MB. The log box at 600+ lines is no problem.
- **Not handled, on purpose:** FFmpeg uninstalled while the program runs (every file fails with "file not found"; rare); paths over 260 characters not tested.
